# Private MCP adapter

`createWorker({readUI, readPage})` wraps the shared Rash MCP protocol. Build `readUI` from the self contained MCP App bundle and `readPage` from the private dashboard shell. Bind an R2 bucket as `RASH_PROJECTS`.

This adapter is intended **only behind the Sites identity gateway**. The gateway must remove user supplied `oai-authenticated-user-id` headers and inject the authenticated identity. Do not expose a direct `workers.dev` route that accepts this header from the public internet. The header is a trust boundary, not a standalone authentication scheme.

`POST /mcp` serves stateless JSON responses. Notifications return 202. GET streaming and session deletion are unsupported and return 405. Initialization, tool schemas, resource templates and the static UI resource are discoverable without project access. All project operations and project resource listings require identity. `GET /` requires identity and serves the injected dashboard. No route enables arbitrary CORS. Requests with Origin are restricted to the current origin and exact ChatGPT or Claude host origins.

Each identity is hashed with SHA 256 to an R2 key prefix. Project IDs must match the full UUID format. Updates compare both the caller's revision and R2's ETag. Failed conditional puts return a revision conflict. Deletion replaces the object with a conditional tombstone containing ID, revision and timestamp, with no project content. This prevents an in-flight writer from reviving deleted content. Tombstone metadata remains stored; deletion is not removal of all storage metadata.

Request bodies are streamed with a 5 MB bound. Stored records are bounded to 5 MB plus envelope space. Shared project complexity validation and 16 MB export bounds apply. A tenant manifest contains at most 100 active project IDs. Conditional manifest writes serialize project admission with at most three retries, so concurrent creates cannot exceed capacity. Listing reads only these IDs; accumulated tombstones never consume listing capacity. Creation writes the project before admitting its ID and removes unpublished content if admission fails. Deletion removes project content before pruning the manifest; subsequent listing or creation recovers interrupted pruning. Unindexed records are not readable through the API. An isolate termination between writing a new record and updating the manifest can leave unreachable content; an operational reconciliation job would be needed to reclaim it. The design does not impose a strict aggregate byte or billing quota. Do not remove tombstones without accounting for in-flight writes.

Run `node --test tests/mcp-cloud.test.js` for fake R2 concurrency, deletion, tenant isolation, concurrent capacity enforcement, 1100 create/delete cycles, body limits and HTTP lifecycle checks. These tests do not prove the deployed identity gateway configuration or native ChatGPT/Claude host behavior. Deployment must also verify two authenticated identities cannot access one another's projects and that a forged external identity header cannot cross the gateway.

Conditional write semantics: [Cloudflare R2 Workers API reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).
